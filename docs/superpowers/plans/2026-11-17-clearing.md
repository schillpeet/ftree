# Clearing around the tiered tree Implementation Plan

> **For agentic workers:** REQUIRED SUB-SKILL: Use superpowers:subagent-driven-development (recommended) or superpowers:executing-plans to implement this plan task-by-task. Steps use checkbox (`- [ ]`) syntax for tracking.

**Goal:** The Stufenbaum stands on a low hill in a forest clearing with grass in the wind, a few rocks, haze with light shafts, and a ring of billboard trees, each part chosen by the user from lab variants.

**Architecture:** `ui/app/clearing.ts` is the pure core (hill shapes, ground height, rock and ring placement, lab variant tables), checked by `clearing.check.mjs`. Stage 1 reuses `Meadow` with a ground function; from stage 2 `ui/app/Clearing.tsx` is the Stufenbaum's own ground, grass, rocks and ring and replaces `<Meadow />` under `organicExperimental`. `useClearingLab()` keeps the open stage's variant and sliders in `localStorage` (`ftree.clearing`).

**Tech Stack:** three 0.187, @react-three/fiber 9, @react-three/drei, @react-three/postprocessing (already installed), TypeScript, `node app/*.check.mjs`.

**Spec:** `docs/superpowers/specs/2026-11-17-clearing-design.md`

## Order (changed 2026-11-17)

Task 5 (forest ring, with the haze density of Task 4 and the camera) runs right after Task 1's drafts, before Tasks 2–4; Task 1's pick waits until the ring stands. Haze colour and light shafts stay in Task 4.

## Global Constraints

- Only `organicExperimental` (Stufenbaum) changes; the organic tree ("3D"), GRID and the landing look as before.
- Every stage starts with 2–3 variants in the lab, screenshots (start view and one close view, noon and sun about 5° high in the forenoon via the lab clock), and the user's pick; build out and commit only after the pick and after the user approved the staged diff.
- After a pick, the losing variants and the stage's lab controls are deleted; the chosen values become constants in `clearing.ts`.
- The tree's foot stays at `TREE_BASE` (`Scene.tsx`); the clearing floor lies `H` below it.
- At least 50 frames per second in the start view at post tier high on an M1 laptop; medium tier gets half the grass blades.
- Commit messages lowercase, imperative: `feat(ui): …`; no pull request unless the user asks.
- `docs/project-overview.md`: one sentence per line, new lines in the tiered tree's section.
- Before pushing: `git fetch origin && git rebase origin/main`, then `pnpm --dir ui typecheck && pnpm --dir ui lint` and every `ui/app/*.check.mjs`.

## Review Focus

- Switching the hill variant while a tree is shown: the roots must follow at once (the tree rebuilds), no floating or buried roots. Task 1, Step 1 checks that `buildTwinedTree` with a different ground moves the roots' tips.
- A one-person family and an empty tree on every hill: no crash, the collar sits on the hilltop. Task 1, Step 1.
- Switching the appearance back to "3D": the organic tree stands on today's meadow, unchanged. Task 1, Step 6 screenshot.
- Panning (right drag, two-finger drag) under `organicExperimental` must not carry the camera out of the ring. Task 5, Step 5.
- Growth replay on the clearing: grass, rocks and ring stay still and the frame rate holds. Task 2, Step 6 and Task 5, Step 6.

**Interfaces:**
- Produces in `clearing.ts`:
  - `export type HillKind = 'goal' | 'flatter' | 'plateau'`
  - `export const HILLS: Record<HillKind, { height: number; foot: number; top: number }>` – goal `{2.5, 35, 0}`, flatter `{4, 25, 0}`, plateau `{3, 30, 15}` (`top` = radius of the flat top)
  - `export function hillAt(kind: HillKind, r: number): number` – 0 at `r ≤ top`, `−height` at `r ≥ foot`, non-increasing; goal and plateau ease with smoothstep between `top` and `foot`; flatter is `−4 · (1 − exp(−(r / 12.5)²))` clamped to `−4` at the foot (a round dome)
  - `export function groundAt(kind: HillKind, x: number, z: number): number` – relative to the hilltop: `hillAt` plus today's ripple (`0.9 · exp(−r²/12000) · noise(x·0.035, z·0.035)`, same `makeNoise(1, 4)`), the ripple multiplied by `smoothstep(foot · 0.5, foot + 10, r)` so the hilltop stays clean
  - `export const DOME = (r: number) => -7 * (1 - Math.exp((-r * r) / 1800))` – today's dome, moved here from `twinedForm.ts`
- Produces in `clearingLab.ts`: `export function useClearingLab(): [ClearingLab, (next: Partial<ClearingLab>) => void]` with `type ClearingLab = { hill: HillKind }` (later tasks add fields), stored as JSON under `ftree.clearing`, default `{ hill: 'goal' }`, same `useSyncExternalStore` + `StorageEvent` pattern as `useAppearance`.
- Produces: `buildTwinedTree(plan, front, name = '', ground: (r: number) => number = DOME)`; `<TwinedTree ground={…} />`; `<Meadow ground={(x, z) => number} />` (default `height`).
